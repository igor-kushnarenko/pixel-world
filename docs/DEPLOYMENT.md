## Автоматическое обновление

Конфигурация: `.github/workflows/pages.yml`. При изменении кода в ветке `main` GitHub Actions:

1. Устанавливает зависимости из lock-файла через `npm ci` под Node.js 24.
2. Проверяет контракт параметров командой `npm test`.
3. Собирает приложение и библиотеку командой `npm run build`.
4. Публикует только содержимое `dist/` через GitHub Pages.

Изменение только документации, журнала и отчётов не запускает повторную публикацию. Ручной запуск доступен в разделе Actions → Publish pixel world to GitHub Pages → Run workflow.

Настройка репозитория: Settings → Pages → Source: **GitHub Actions**.

## Пути к ресурсам

Workflow получает корневой путь Pages и передаёт его сборке через `PAGES_BASE_PATH`. Vite записывает правильный префикс в JS, CSS, favicon, пути к текстурам и навигационные ссылки. Локальный запуск без переменной сохраняет прежнее поведение.

Проверка перед публикацией в PowerShell:

```powershell
$env:PAGES_BASE_PATH = '/pixel-world/'
npm run build
npm test
npm run test:browser
```

Браузерный тест использует тот же путь `/pixel-world/`, а не только корень локального сервера.

## Содержимое репозитория

Публикуются код, каноническая спецификация, документация, журнал, тесты и PNG, необходимые проекту. Исходный PSD, локальные Python-зависимости, `node_modules`, архивы и рабочие снимки остаются в локальной папке и исключены через `.gitignore`. Подготовленные слои из PSD уже включены в `public/assets/nightcity/psd/`, поэтому сборка сайта не требует Photoshop или Python.

Исходный PSD можно подключить локально по пути из `manifest.json` для повторного импорта и дополнительной проверки SHA-256. Браузерные тесты также работают в клоне без PSD: проверяются все включённые PNG, а наличие локального PSD отмечается в отчёте отдельно.

## Проверка опубликованной сцены

```sh
node tools/check-deployment.mjs https://igor-kushnarenko.github.io/pixel-world/
```

Тест открывает публичный адрес в браузере, проверяет HTTP-ответ, загрузку четырёх городских планов, канонический старт, режим «По PSD», облака, анимацию, выгрузку пресета и навигацию внутри проекта. Результат — `artifacts/deployment-report.json`; снимок — `artifacts/published-site.png`.

Комната и отдельные световые маски реального города остаются следующим этапом разработки; публикация сохраняет текущую проверенную композицию.
